## Regole fondamentali prima di spostare un file

1. **Desktop:** [`apps/desktop-shared/editor/sources.json`](../apps/desktop-shared/editor/sources.json) decide l'ordine di concatenazione dei sorgenti JS.
2. **Android:** [`apps/android/editor/sources.json`](../apps/android/editor/sources.json) definisce un ordine di concatenazione diverso.
3. [`scripts/release/prepare.py`](../scripts/release/prepare.py) compone il codice condiviso e gli asset offline. Questi file JS **non sono moduli ES indipendenti**: alcune estensioni si aspettano variabili e prototipi disponibili nello stesso ambito.
4. Dopo un eventuale spostamento, aggiornare manifest, `prepare.py`, HTML, bridge, asset e test. Validare entrambi gli editor, non solo la sintassi JS.
5. **Non modificare output generati** (come il bundle `architect.js` di Android) al posto dei sorgenti; non intervenire nelle directory `legacy/` per correggere la release corrente.
6. Separare core offline, bridge/cloud e attivazione Developer. Non introdurre segreti o dipendenze Cloud obbligatorie nel motore comune.

## Ricerca rapida (Windows PowerShell, macOS, Linux)

```bash
git ls-files '*state.js' '*layout.js' '*recovery*' '*cloud*'
git grep -n -e deleteSelected -e layoutRadialOrganic -e loadAutosave -- apps packages
npm test
npm run test:build
```

Per test browser mirati, dal checkout con i prerequisiti Playwright installati:

```bash
npx playwright test tests/browser/node-chaos-keyboard-viewport.spec.js
```

Le build e i collaudi sono **locali**, senza avviare GitHub Actions. Leggere [`docs/DEVELOPMENT.md`](DEVELOPMENT.md) e le guide delle app prima di compilare. **Non equiparare** test isolati, suite Node, test Playwright e prove native EXE/DMG/APK.

**OCR 2.0:** [stato e limiti](roadmap/GLAUKA_OCR_2.md), [benchmark e prove](qa/2026-11-11-ocr2-audit-and-benchmark.md). Il core canonico `apps/desktop-shared/editor/ocr-structure.js` è condiviso nel bundle Android lazy `ocr-tools`, non duplicato.
